# 对表使用指南

[返回项目说明](../README.md) · [English overview](README.en.md)

## 1. 准备两份表

对表适合比较同一类清单的两个版本，例如上周与本周的设备表、导出前后的联系人表。两份表都应有标题行，并至少包含一列能稳定标识每条记录的编号。

支持 UTF-8 编码、逗号分隔的 CSV 和基础 XLSX。单个文件不能超过 8 MB；每个所选工作表最多 20,000 个数据行、100 列和 500,000 个单元格。接近上限时，实际可用容量还取决于浏览器内存和设备性能。

XLSX 可以包含多个工作表。未明确选择时，对表会依次检查前 32 张工作表，跳过空表或表头无效的表，读取首张有效表，并在页面提示跳过的工作表和原因。超出大小、行列或单元格限制的工作表，以及损坏的 XLSX，会直接报错，不会继续自动尝试后续表。

选择文件后，请为“旧表”和“新表”分别确认实际读取的工作表。可以通过下拉框明确改选；若选中的表为空或表头无效，页面会报错并保留下拉框，可直接选回有效表。工作表名称相同并不保证内容含义相同，仍需检查列名和样例数据。

## 2. 选择对齐列

对齐列相当于每行的身份证。优先选择设备编号、订单号等稳定且唯一的列，不要选择姓名、状态或日期等可能重复或变化的字段。

编号按文本处理并默认精确匹配：

- `001` 与 `1` 是不同编号；
- `A01` 与 `a01` 默认不同；启用“忽略大小写”后可视为相同；
- ` A01 ` 与 `A01` 默认不同；启用“忽略首尾空白”后可视为相同。

如果系统导出时丢失了前导零，应先在源系统或表格中统一编号格式。不要仅为了让结果看起来一致而盲目开启忽略选项。

## 3. 处理空键与重复键

对表会列出两类编号问题，并标明来自“旧表”还是“新表”及相关行号：

- **空编号**：该行无法与另一份表建立可靠对应关系；
- **重复编号**：同一侧有多行使用同一编号，无法确定哪一行应该参与一对一比较。

开始解释差异前，应回到原表修正这些行，再重新导入。若业务上确实允许同一编号出现多次，请先生成真正唯一的组合编号列，例如“订单号 + 明细序号”，再用该列对齐。

## 4. 阅读结果

结果分为四种状态：

- **新增**：编号只在新表中出现；
- **删除**：编号只在旧表中出现；
- **修改**：两边都有该编号，但至少一个比较字段的值不同；
- **未变化**：两边都有该编号，比较字段的值一致。

修改记录会列出字段名、原值和新值。新增列和删除列也应单独核对，因为列结构变化可能影响对结果的理解。

忽略空白或大小写只影响比较归一化，不会把原表改写成新的格式。原文件始终只读。

## 5. 导出报告

可以下载 CSV 或 JSON：

- CSV 适合在常见表格软件中筛选和查看；
- JSON 保留结构化的汇总、差异、字段变化和诊断信息，适合程序处理或审计归档。

为降低电子表格公式注入风险，CSV 导出会对以 `=`, `+`, `-`, `@` 等公式触发字符开头的值添加安全前缀。该前缀属于导出保护，原文件不会被修改。把报告交给他人前，仍应检查其中是否含有个人信息、账号、内部编号或其他敏感数据。

## 6. XLSX 与隐私边界

- XLSX 公式只使用文件内已有的缓存结果；对表不会执行、刷新或重新计算公式。若缓存结果缺失或过期，应先在可信的表格软件中重新计算并保存。
- 对表面向单元格值，不保证复杂格式、颜色、条件格式、图表、宏、批注、图片或合并单元格语义的保真。
- 文件在当前浏览器页面本地解析，应用不会主动上传内容。刷新或关闭页面会清除当前页面数据；已经下载的报告由用户自行保管和删除。
- 浏览器崩溃、内存不足或设备性能限制可能使低于标称上限的文件也无法完成解析。遇到问题时可删除无关列、拆分数据，或另存为 CSV 后重试。

## 7. 建议的复核顺序

1. 确认两边选择了正确文件和工作表。
2. 确认对齐列含义一致，并先解决空编号和重复编号。
3. 检查新增列、删除列及差异汇总。
4. 抽查若干新增、删除和修改记录，对照原文件验证。
5. 下载所需格式，并按数据敏感级别保存或传递报告。
